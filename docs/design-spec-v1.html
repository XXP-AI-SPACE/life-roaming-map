01 · 结论先行

这个项目最容易被做错的地方，是把「地图」当成底图来做：接一个地图 SDK、拿定位、打点。但在个人主体、零预算、只给自己看的前提下，正确解法是反过来的——地图只是索引，不是地理信息产品。一张 59KB 的自绘中国地图，加上「省市区 + 一张照片 + 一句话」的记录模型，就能把产品的核心价值交付完。

结论 1
地图自绘，不接 SDK
省界数据来自标准地图数据源，简化后 59KB，离线可画、零 key、零额度、零审图风险。代价是没有缩放与街道级细节——而 MVP 根本不需要。
结论 2
点位精确到「省/市/区」，不到坐标
个人主体没有 wx.getLocation 权限，也不需要。手动三级选择器是唯一解，且比精确定位更符合「回忆」这件事的粒度。
结论 3
一次只存一张照片
限制是产品力：30 秒记完一段。多图相册会把产品拖进「整理照片」的重活里，而那正是用户想逃离的事。
结论 4
点亮比列表更有驱动力
34 个省级行政区天然是一个进度条。地图的颜色变化比「共 N 条记录」更能让人想再记一条。

本次实际交付了什么

  • 小程序代码：新增 4 个页面（地图 / 足迹 / 新增 / 详情）+ 3 个工具模块，入口改为地图页，云开发集合与存储链路打通（静态校验全绿）。
  • 地图数据：从 582KB 的 GeoJSON 压到 59KB 的 SVG path，35 个区域（含台湾省、香港、澳门、南海诸岛），中文标签位置逐个校过。
  • H5 体验版：单文件 141KB，浏览器直接打开就能完整走一遍「点省份 → 记一段 → 足迹 → 详情 → 删除」，localStorage 持久化，22 项端到端断言全部通过。
  • 方案与思维导图：即本文档 + 一张全日成果导图，含 12 条决策日志与 11 项存疑清单。

03 · 产品定义

把你走过的省、拍下的那一张照片，钉在一张中国地图上。不是旅行攻略，不是打卡社交，是一份只有自己能看的空间记忆。

为谁做

先是一个人：你自己。个人主体、无营业执照、不打算做多用户运营。这个前提决定了后面所有取舍——没有公开主页、没有关注/评论、没有邀请裂变，也就不需要内容审核、举报入口、用户协议之外的合规设计。

三个真实场景

场景触发时刻产品要做什么
回来那天旅行结束、照片还在相册里没整理30 秒记一条：选地点、选一张、写一句话，结束
无聊翻看深夜、通勤、等人打开地图，看哪块亮着，点进去看那天的照片
计划下一次看到别人去了某地、或想「还差几个省」一眼看出空白区域，形成「想去」的冲动

明确不做的事

  • 不做定位打卡——个人主体无 wx.getLocation，也不值得为此申请企业资质。
  • 不做路线规划——那是地图 App 的事，不是记忆产品的事。
  • 不做多图相册——一张照片是「一段记忆」的隐喻，多了就变成相册管理。
  • 不做社交——Phase 2 再议，且必须是不公开的（只分享单条记忆卡片）。
  • 不做城市级热力图/统计报告——MVP 阶段的数据量撑不起，也容易变成装饰。

成功的样子（MVP 验收标准）

指标目标怎么算
记一条的耗时≤ 30 秒从点「记录」到保存成功，含选照片
首次可用≤ 3 步打开 → 点省份 → 记录
地图可读性一眼认出 5 个点亮省真机 375px 宽度下，不看文字也能分辨
数据不丢换设备可恢复云开发同 openid 拉取历史记录

04 · 信息架构与流程

只有两个一级入口：地图和足迹。同一个数据，两种看法——空间视角与时间视角。新增是动作，不是页面层级，所以做成悬浮按钮而不是第三个 Tab。

主路径走查

步动作系统反馈失败/空态
1打开小程序地图铺满，未点亮为米色；标题下方显示「已点亮 0 个省份」集合不存在 → toast 说明怎么建
2点「广东」广东变深赭色，底部弹层出现「广东省 / 这里的空白，等你来填」点到海上 → 无反应（不误触）
3点「在这里记录」新增页滑出，省份已预填「广东省」—
4选一张照片压缩后填入 4:3 相框，右下角「重选」取消选择 → 保持原样
5选城市/区县、写标题保存按钮由灰转赭缺任一项 → toast 提示缺什么
6点「记下这一段」「已记下」→ 返回地图，广东保持点亮，统计 +1上传失败 → 弹窗说明，表单不丢
7切「足迹」本月分组下出现新卡片无记录 → 空态 + 去地图
8点卡片 → 删除二次确认后，DB 与云存储文件一起删，地图取消点亮删除失败 → 弹窗，记录保留

05 · 地图方案（含合规）

地图是这个产品唯一的「重资产」，也是最容易踩合规线的地方。本次选择自绘 + 标准地图数据源，并用一条可复现的脚本把 582KB 的 GeoJSON 压到 59KB。

四种地图路线对比

方案包体/成本能力风险结论
自绘 SVG / Canvas59KB，零 key省份着色、点选、离线可画无缩放/街道；边界需注明来源✅ MVP 采用
微信 <map> 组件零包体，需网络真地图、可叠 polygon瓦片加载慢、省份着色需自绘 polygon、样式受限备选（做「到访点」时）
腾讯地图 GL / JS SDK需 key、有额度最强：检索、路线、聚合个人主体申请与配额、key 泄露Phase 2
地图图片 + 热区图片体积大只能点击，不能着色分辨率与热区坐标难维护否

数据管线（可复现）

地图规格

项值
区域数35 = 34 个省级行政区 + 南海诸岛
viewBox0 0 1000 979（含南海诸岛的真实相对位置，不做内嵌小窗）
投影Web Mercator，纬度转角度当量后与经度同量纲，保证宽高比不失真
简化策略常规省份 0.1° 取整 + Douglas-Peucker 0.08°；台湾 / 港澳 / 南海诸岛 0.02° + 0.01° 且不过滤小面
体积59.0 KB（其中路径字符 56,764）
标签29 个省份文字 + 5 个直辖市/特区「圆点 + 偏移文字」+ 南海诸岛
命中测试射线法点在多边形内；直辖市/特区优先（被邻省外环包住），再加 30 单位半径兜底
绘制顺序常规省份 → 直辖市/特区 → 南海诸岛（避免被邻省填充覆盖）

合规要点（必须遵守）

要求本项目怎么做的
数据源合规只用 DataV.GeoAtlas（源自自然资源部标准地图数据），不接 Google / Apple / Bing / OpenStreetMap / Mapbox
领土完整台湾省、香港特别行政区、澳门特别行政区均为独立可点区域；南海诸岛按数据源形态完整绘制
不自行编造边界十段线不在数据源中，因此不手绘；只渲染数据源给出的 10 组岛礁多边形，避免「画错」风险
不涉及敏感位置不采集坐标、不标注军事/涉密单位，记录只到区县一级
个人信息照片与地点只存自己的云环境，集合权限「仅创建者可读写」，无公开页、无批量导出
来源标注地图页脚注「地图数据：DataV.GeoAtlas」，正式提审时在「关于」补完整来源说明
一条硬提醒：自绘边界图不等于「标准地图」。如果将来把它印在包装、宣传物料上，或对外宣称是行政区划图，就进入《地图管理条例》的审核范围。MVP 只在小程序内做「个人足迹示意」，并按上表标注来源——这是边界，别越。

06 · 数据模型与云开发

一个集合、一个存储目录，够用。没有用户表——云开发会自动给每条记录写 _openid，配合「仅创建者可读写」的集合权限，隔离是免费的。

集合 memories

字段类型必填说明
_idstring自动云开发主键
_openidstring自动写入者身份，权限隔离依据
titlestring是一句话标题，≤ 24 字
provincestring是省/直辖市/特区全称，取自 picker mode="region"
citystring否市；直辖市存同名
districtstring否区县
datestring是YYYY-MM-DD，用于排序与分组
notestring否备注，≤ 200 字
fileIDstring是云存储文件 ID（cloud://...），直接给 <image> 用
createdAtnumber是毫秒时间戳，同日期时的次级排序

存储与权限

项设置
集合权限「仅创建者可读写」——控制台 → 数据库 → memories → 权限设置
照片路径memories/{时间戳}-{随机6位}.{ext}，与记录一一对应，删除时同步删文件
图片尺寸客户端 chooseMedia 已开 sizeType: compressed；实测 900×675 原图约 21KB，压缩后更小
查询orderBy('date','desc') + orderBy('createdAt','desc')，上限 100 条

错误翻译（这层很关键）

云开发的报错对普通用户毫无意义。代码里把几个高频错误翻成了可执行的话：

// utils/db.js
-502005  → "数据表还没有创建：请在云开发控制台新建集合 memories，权限选「仅创建者可读写」"
-502003  → "云数据库权限不足或环境异常，请检查环境 ID 与集合权限"
timeout  → "网络不太顺畅，请稍后重试"
为什么在意这个：这个项目只有你一个人用，出问题时唯一的「客服」就是这条 toast。一句「数据表还没有创建」比 errCode: -502005 省下半小时。

07 · 页面与交互

四个页面

页面关键实现状态与边界
地图
pages/map		 Canvas 2D 按 windowWidth - 40 定宽、按 1000:979 定高；dpr 缩放保证高清；bindtouchend 取坐标反算地图单位后命中测试 空态：地图下方一句「点一下省份，记下第一段旅程」；加载态文案「正在翻开你的地图…」；集合缺失 → toast
足迹
pages/album		 按月分组（date.slice(0,7)），卡片 = 168rpx 方图 + 标题 + 地点 + 备注 2 行 + 日期 空态：两行说明 + 「去地图看看」；下拉刷新；底部「— 就记到这里 —」
新增
pages/add		 chooseMedia（1 张、压缩）→ 云存储；picker mode="region" 三级选择；日期默认今天；标题 24 字、备注 200 字计数 缺照片/地点/标题分别给不同提示；保存中禁用防重复；失败弹窗且表单不丢
详情
pages/detail		 大图 aspectFill 620rpx，点击 previewImage；删除走二次确认，同时删 DB 与云存储 加载「正在翻开…」；找不到 → 空态 + 返回

交互上的几个判断

  • 省份弹层而不是跳页：点省份先看到「这里有几段记忆」，再决定看不看或加一段。少一次跳转，多一次犹豫的空间。
  • 从省份进入新增会预填省：用户已经表达了「我要记广东」，就不该让他再选一次。实现上用 preset 字段兜住（picker 需要合法三级数组，不能塞半截）。
  • 圆点 + 偏移标签处理京津沪港澳：这 5 个区域在 343px 宽度下只有几像素，直接写地名必然重叠。做法是画点、文字外移、命中区放大到 30 单位。
  • 「重选」而不是删除照片：单图场景下，用户要的是换一张，不是先删再选。
  • 保存成功才返回：先 toast「已记下」再 navigateBack，避免返回后看不到反馈。

08 · 技术选型对比

存储：云开发 vs 本地 vs 自建

方案优势代价结论
云开发 DB + 存储免鉴权（_openid 自动隔离）、免费额度、无需服务器冷启动、配额、环境绑定✅ 小程序采用
本地 Storage零成本、离线、秒开换设备即丢、10MB 上限H5 体验版采用（演示够用）
自建后端完全可控、可迁移个人主体要买服务器、备案、鉴权全自己写否

渲染：Canvas vs SVG vs 组件

端选择原因
小程序Canvas 2DWXML 不支持 <svg>，也没有 Path2D；路径字符串自己解析成 moveTo/lineTo 是最稳的
H5 体验版内联 SVG每个省份是独立 <path>，点击/hover/高亮全靠 CSS，零重绘成本
共用同一份 path 数据两端视觉一致，改边界只改一个文件

记录粒度：省 vs 市 vs 坐标

粒度点亮逻辑用户成本结论
省级清晰：一个省一个色块最低✅ 地图着色按省
市级需要市级边界数据（体积 ×5）中记录里存市，地图不按市着色
坐标需要定位权限高（个人主体做不到）否

09 · 设计启示

做这个 MVP 的过程里，有几条判断可能比代码更值得留下。

1. 地图不是底图，是索引

一开始最容易想到的是「接高德/腾讯地图，打点」。但用户打开这个 App 不是为了知道自己在哪，而是为了确认「我去过那儿」。索引只需要「可辨认 + 可点击 + 可着色」，不需要街道、不需要缩放。想清楚这一点，59KB 就替代了 3MB 的 SDK。

2. 限制是产品力

「一次只能一张照片」看起来是功能缺失，实际是把「整理旅行照片」这件苦活挡在门外。用户要的是 30 秒留下一段记忆，不是第二个相册。凡是会增加记录成本的功能，MVP 阶段一律不做。

3. 数据源决定合规上限，不是美化项

台湾、港澳、南海诸岛怎么画，不是设计风格问题，是能不能上线的问题。本次的做法是「数据源给什么就画什么，绝不自行补线」：十段线不在数据里，就不手绘；岛礁多边形在数据里，就完整保留。这样即使被问「你这图哪来的」，答案是可追溯的。

4. 点亮本身就是进度条

34 个省级行政区是一个天然的完成度系统，比任何「已记录 N 条」都有驱动力。这也解释了为什么地图页的统计是「已点亮 X 个省份」而不是「共有 N 条记录」——前者是目标，后者是账本。

5. 双端同构让验证变便宜

小程序没法在无头环境里跑，但地图逻辑是纯 JS。map-core.js 不依赖任何 wx.*，所以能在 Node 里跑单测（35 个区域的标签点必须命中自己）、能在浏览器里真实绘制并截图验证。H5 体验版则把整个交互链路变成可断言的 22 个用例。这套「逻辑层可测、表现层可截」的结构，比「改完发到手机上点点看」快一个数量级。

11 · 存疑清单

按「会不会挡住真机跑通」排序。P0 不解决，代码跑不起来；P1 影响体验或合规；P2 可以先放着。

级别问题影响建议动作
P0 云环境 ID 仍是模板环境 YOUR_ENV_ID 数据会写进模板环境，可能与你其他项目混在一起，也可能随时被清理 在云开发控制台建自己的环境，改 miniprogram/config.js 一行即可
P0 集合 memories 尚未创建 首次保存会报 -502005（已有中文提示，但功能不可用） 控制台新建集合，权限选「仅创建者可读写」；建议建 3 个索引（date、createdAt）
P0 类目匹配：个人主体「工具 → 备忘录」是否允许照片上传 提审可能被驳回（含图片上传与云存储） 提审前查最新类目要求；若不允许，降级为纯文字记录（数据模型已兼容）
P1 自绘边界不是「审图号」地图 若用于宣传物料或对外宣称行政区划图，可能触及地图审核 小程序内标注来源；对外物料不使用该图
P1 云存储免费额度与流量 照片虽压过，但长期记录会累积；超出后可能产生费用或写入失败 先在控制台看免费额度；给上传失败加更明确的提示
P1 照片 EXIF 方向（部分安卓竖拍会横过来） 详情页大图方向错误，体验硬伤 上传前用 canvas 重绘（H5 端已做，小程序端待补）
P1 列表上限 100 条 超过 100 条后老记录不显示，但地图统计仍按 100 条算 下一版改分页或按年加载；短期够用
P1 直辖市/特区命中依赖 30 单位半径兜底 343px 宽度下可能误命中邻省（北京/天津、港澳/广东） 真机 375/390/414 三档各测 10 次点击，必要时按机型调半径
P2 tabBar 无图标，视觉偏素 不影响功能，影响完成度观感 补 2 个 81×81 单色图标（地图 / 列表）
P2 模板组件 agent-ui 约 300KB 未使用 包体浪费、审核时可能被问「AI 对话功能为何未使用」 确认不做 AI 后删除；保留则补一句产品说明
P2 省份全称与简称的映射靠字符串清洗 若未来出现新简称（如「内蒙古」写成「内蒙」）会点亮失败 把归一化规则收进 map-core.js 并加单测（已有 7 例）
